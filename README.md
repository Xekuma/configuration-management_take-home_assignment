# Транслятор учебного конфигурационного языка в XML (Вариант №4)

## 1. Общее описание

Консольный инструмент командной строки для трансляции текстовых конфигураций, написанных на учебном конфигурационном языке, в формат XML.

Входной файл передаётся через ключ командной строки, а сформированный XML выводится в стандартный поток вывода (`stdout`). При обнаружении синтаксических или файловых ошибок программа выводит сообщение с указанием номера строки и столбца в поток ошибок (`stderr`) и завершается с ненулевым кодом возврата.

### Поддерживаемый синтаксис входного языка

| Конструкция | Синтаксис | Пример |
| --- | --- | --- |
| Однострочный комментарий | `-- <текст до конца строки>` | `-- Это однострочный комментарий` |
| Многострочный комментарий | `=begin ... =end` | `=begin`<br>`Текст`<br>`=end` |
| Целое число | `[+-]?\d+` | `0`, `+42`, `-17` |
| Имя (идентификатор) | `[_a-z]+` | `map_width`, `_base` |
| Массив | `array( значение, значение, ... )` | `array(1, array(-2, +3), array())` |
| Объявление константы | `def имя: значение;` | `def gravity: -980;` |
| Вычисление константы | `! {имя}` | `! {gravity}` |

Значениями являются числа и массивы (допускается произвольная вложенность массивов и констант). Объявления `def` вычисляются на этапе трансляции и в выходной XML не попадают — в XML выводятся только итоговые значения.

### Формат выходного XML

* Корневой элемент: `<config>`.
* Числа преобразуются в элементы `<number>...</number>`.
* Массивы преобразуются в элементы `<array>...</array>`, содержащие вложенные `<number>` и `<array>`.

## 2. Описание всех функций и настроек

### Аргументы командной строки (настройки запуска)

| Аргумент | Обязательность | Описание |
| --- | --- | --- |
| `-i`, `--input <путь>` | Обязательный | Путь к входному файлу на учебном конфигурационном языке (чтение в кодировке `UTF-8` / `UTF-8 with BOM`). |
| `-h`, `--help` | Необязательный | Вывод справки по использованию CLI. |

Коды завершения процесса:
* `0` — трансляция выполнена успешно, XML выведен в `stdout`.
* `1` — ошибка чтения файла или синтаксическая ошибка, диагностика выведена в `stderr`.

### Константы конфигурации в `src/main.py`

* `SINGLE_LINE_COMMENT = "--"` — префикс однострочных комментариев.
* `NUMBER_RE = re.compile(r"[+-]?\d+")` — регулярное выражение для целых чисел.
* `RAW_IDENT_RE = re.compile(r"[_a-zA-Z][_a-zA-Z0-9]*")` — шаблон захвата идентификаторов для последующей валидации.
* `VALID_NAME_RE = re.compile(r"^[_a-z]+$")` — проверка допустимости имени константы.
* `KEYWORDS = {"def": "DEF", "array": "ARRAY"}` — таблица ключевых слов языка.

### Классы и методы (`src/main.py`)

#### `ConfigSyntaxError(Exception)`
Исключение для всех лексических, синтаксических и семантических ошибок (например, обращение к необъявленной константе).
* `__init__(message, line, col)` — формирует сообщение с указанием номера строки (`line`) и столбца (`col`).

#### `Token`
Неизменяемый `dataclass`, описывающий один токен: тип (`kind`), исходный текст (`value`), строку (`line`) и столбец (`col`).

#### `Lexer`
Лексический анализатор: разбивает входной текст на последовательность токенов, игнорирует пробельные символы и комментарии.
* `__init__(text)` — инициализирует буфер текста, позицию и счётчики `line`/`col`.
* `_advance(count=1)` — сдвигает курсор вперёд и обновляет координаты строки и столбца.
* `_is_word_boundary(index)` — проверяет, что после директивы (`=begin`, `=end`) не идёт буква, цифра или `_`.
* `_starts_multiline()` / `_ends_multiline()` — определяют начало (`=begin`) и конец (`=end`) многострочного комментария.
* `_starts_single_comment()` — проверяет наличие префикса однострочного комментария `--`.
* `_skip_single_comment()` — пропускает символы до конца текущей строки.
* `_skip_multiline_comment()` — пропускает блок `=begin ... =end`; если `=end` не найден до конца файла, выбрасывает `ConfigSyntaxError`.
* `_read_number(match)` — формирует токен `NUMBER` и проверяет отсутствие склеенных с числом букв или `_`.
* `_read_identifier(match)` — валидирует имя по `[_a-z]+` и возвращает токен ключевого слова (`DEF`, `ARRAY`) или `NAME`.
* `_next_token()` — распознаёт следующий токен или пропускает пробелы/комментарии; на неизвестном символе выбрасывает `ConfigSyntaxError`.
* `tokenize()` — прогоняет весь текст через `_next_token()` и завершает список токеном `EOF`.

#### `Parser`
Синтаксический анализатор (метод рекурсивного спуска) с одновременным вычислением констант этапа трансляции.
* `__init__(tokens)` — сохраняет список токенов, текущую позицию и словарь констант `constants`.
* `current` — свойство, возвращающее текущий токен.
* `_advance()` — переходит к следующему токену и возвращает предыдущий.
* `_format_got(tok)` — форматирует неожиданный токен для текста сообщения об ошибке.
* `_expect(kind, expected_desc)` — проверяет тип текущего токена и сдвигает позицию либо выбрасывает `ConfigSyntaxError`.
* `parse()` — разбирает верхний уровень файла (объявления `def` и значения) до токена `EOF`.
* `_parse_const_decl()` — разбирает `def имя: значение;` и сохраняет вычисленное значение в `self.constants`.
* `_parse_value()` — разбирает число, массив или вычисление константы.
* `_parse_array()` — разбирает `array(...)`, включая пустые массивы и многоуровневую вложенность.
* `_parse_const_eval()` — разбирает `! {имя}` и подставляет значение объявленной константы (или выбрасывает `ConfigSyntaxError`, если константа не объявлена).

### Функции уровня модуля (`src/main.py`)

* `_append_xml_value(parent, value)` — рекурсивно добавляет число (`<number>`) или массив (`<array>`) в XML-дерево.
* `translate(text)` — выполняет полный цикл: лексический анализ -> разбор -> построение отформатированного XML с декларацией `<?xml version='1.0' encoding='utf-8'?>`.
* `_configure_stdio()` — переводит потоки `stdout` и `stderr` в кодировку `UTF-8`.
* `_build_arg_parser()` — настраивает `argparse.ArgumentParser` с обязательным ключом `-i` / `--input`.
* `main(argv=None)` — точка входа CLI: читает входной файл, вызывает `translate()`, печатает XML в `stdout` или ошибку в `stderr` и возвращает код завершения.

## 3. Описание команд для сборки проекта и запуска тестов

### Требования и сборка

Проект написан на **Python 3.9+** с использованием только стандартной библиотеки (`argparse`, `re`, `sys`, `xml.etree.ElementTree`, `dataclasses`, `pathlib`, `typing`). Отдельная сборка и установка внешних пакетов не требуются.

Проверка версии Python:

```powershell
python --version
```

Базовый запуск транслятора из корня проекта:

```powershell
python src/main.py -i <путь_к_файлу.cfg>
```

### Запуск тестов

Тестовые сценарии оформлены в виде PowerShell-скриптов (`.ps1`) в папке `tests/` и запускаются из корня проекта:

```powershell
# 1. Проверка всех конструкций языка и их вложенности
.\tests\test_syntax.ps1

# 2. Проверка диагностики синтаксических и файловых ошибок
.\tests\test_errors.ps1

# 3. Проверка 2 примеров из разных предметных областей
.\tests\test_examples.ps1
```

Если в Windows политика выполнения PowerShell блокирует запуск `.ps1`, скрипты можно выполнить с флагом `Bypass`:

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\test_syntax.ps1
powershell -ExecutionPolicy Bypass -File .\tests\test_errors.ps1
powershell -ExecutionPolicy Bypass -File .\tests\test_examples.ps1
```

## 4. Примеры использования

### Пример 1: конфигурация 2D-игры (`tests/game_config.cfg`)

Входной файл:

```text
=begin
Конфигурация игрового уровня:
размеры карты, физика и координаты точек спавна.
=end

-- Базовые параметры мира
def map_width: 1920;
def map_height: 1080;
def gravity: -980;

-- Точки спавна игроков (пары координат x, y)
def spawn_left: array(-400, 120);
def spawn_right: array(+400, 120);
def spawn_points: array(! {spawn_left}, ! {spawn_right});

-- Волны врагов: [номер_волны, количество, скорость]
def wave_one: array(1, 10, 150);
def wave_two: array(2, 18, 210);

array(
    array(! {map_width}, ! {map_height}),
    ! {gravity},
    ! {spawn_points},
    array(! {wave_one}, ! {wave_two})
)
```

Команда запуска:

```powershell
python src/main.py -i tests/game_config.cfg
```

Результат в `stdout`:

```xml
<?xml version='1.0' encoding='utf-8'?>
<config>
  <array>
    <array>
      <number>1920</number>
      <number>1080</number>
    </array>
    <number>-980</number>
    <array>
      <array>
        <number>-400</number>
        <number>120</number>
      </array>
      <array>
        <number>400</number>
        <number>120</number>
      </array>
    </array>
    <array>
      <array>
        <number>1</number>
        <number>10</number>
        <number>150</number>
      </array>
      <array>
        <number>2</number>
        <number>18</number>
        <number>210</number>
      </array>
    </array>
  </array>
</config>
```
